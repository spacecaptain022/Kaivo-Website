# can you give me a design.md for this for the website for Kaivo

Yes — below is a clean `design.md` you can use as the website design spec for Kaivo, based on the visual system in your attached comps and the available Kaivo brand material. The attached comps consistently establish a minimal split-layout language, a light neutral base, a bright aqua map/utility accent, oversized Swiss-style typography, thin technical linework, and the core message shift from “search” to “delegation.”[^1][^2][^3][^4][^5]

## design.md

```md
# Kaivo Website Design System

## Overview

Kaivo’s website should feel like a transition engine: moving the user from lookup to action, from manual search to autonomous delegation. The visual language should communicate precision, motion, infrastructure, and intelligent routing rather than generic “AI futurism.” [file:5][file:6][file:3]

The design direction is editorial-tech minimalism with a transport/control-system metaphor. The current creative points to a Swiss grid, oversized type, air-traffic/map overlays, pixel utility icons, and highly restrained interface framing. [file:5][file:6][file:1][file:4]

## Core Brand Idea

**Primary narrative:** Search never finished the job. Delegation does. [file:3][file:4]

**Website message arc:**
1. Users begin with search.
2. Search returns information, not outcomes.
3. Kaivo turns intent into delegated execution.
4. The destination matters more than the query.
5. Kaivo is the operating layer between asking and getting done. [file:5][file:6][file:3]

## Creative Direction

### Positioning feel

The site should feel:
- Precise
- Sparse
- Intelligent
- Systemic
- Directional
- Quietly futuristic [file:5][file:6][file:3]

It should **not** feel:
- Glossy SaaS template
- Chatbot brand
- Neon AI startup
- Playful consumer app
- Over-illustrated or overly animated product marketing page [file:5][file:6]

### Visual metaphor

The strongest metaphor in the comps is **origin to destination**. The left side represents search, query, or user intent; the right side represents routing, gating, and delegated arrival. This is reinforced through the split screen, the “>” directional marker, map textures, gate/flight microcopy, and connector lines. [file:5][file:6]

Use this as the system-wide interaction model:
- Inputs = origins
- Agents/workflows = routing layer
- Outputs/actions = destinations [file:5][file:6]

## Design Principles

### 1. Use contrast, not clutter
The strongest compositions rely on large empty fields, bold typography, and a single accent zone. Keep layouts sparse and intentional. [file:5][file:6]

### 2. Build around directional flow
Pages should visually move left-to-right or top-to-bottom toward execution. Lines, arrows, anchors, map traces, and transitions should reinforce movement. [file:5][file:6][file:4]

### 3. Make type do the heavy lifting
Typography is the primary visual device. Large words, broken lines, cropped letterforms, and asymmetric text blocks should carry hero sections before cards or illustrations do. [file:5][file:6]

### 4. Treat graphics like system artifacts
Icons, circles, traces, gates, locator marks, and map blocks should feel like operational overlays, not decorative stickers. [file:5][file:6][file:4]

### 5. Keep the interface editorial
The site should feel designed more like a high-concept brand editorial or aviation console than a standard SaaS landing page. [file:5][file:6][file:3]

## Color System

### Primary palette

**Base background:** very light warm-gray or soft neutral  
Suggested: `#ECEBE8` to `#F1F0EC` [file:5][file:6][file:3]

**Primary text:** near-black  
Suggested: `#111111` or `#151515` [file:5][file:6]

**Accent field:** Kaivo aqua / delegation teal  
Suggested: `#4EDFD3` to `#56E3D6` [file:5][file:6][file:1][file:4]

**Accent dark:** deep teal for overlays/map inset  
Suggested: `#214F4B` to `#2C5B56` [file:5][file:6]

**Secondary line gray:** soft technical gray  
Suggested: `#8D8D8A` to `#A7A7A2` [file:5][file:3]

### Color behavior

Use aqua as a **zoned color**, not a general accent spread across everything. In the strongest comp, color is powerful because it is concentrated in the destination side rather than sprinkled around the whole frame. [file:5][file:6]

Recommended ratio:
- 70–80% neutral background
- 10–20% black text and system framing
- 10–15% aqua emphasis [file:5][file:6]

### Dark mode

If dark mode exists, it should invert into:
- charcoal background
- soft off-white typography
- preserved aqua as routing/action signal

Do not turn dark mode into blue-purple cyberpunk. The aqua should remain infrastructural and clean. This follows directly from the restraint of the existing visual language. [file:5][file:6]

## Typography

### Typographic personality

Typography should be:
- Swiss
- Grotesk
- Oversized
- Clean
- Slightly compressed if needed
- Confident enough to hold a composition alone [file:5][file:6][file:3]

### Recommended font stack

**Primary sans:**
- Neue Haas Grotesk
- Suisse Int’l
- Söhne
- Inter Tight
- General Sans

**Fallback web stack:**
- `Inter`, `Helvetica Neue`, `Arial`, `sans-serif`

The comps point clearly toward a modern grotesk system with minimal personality distortion and strong geometric confidence. [file:5][file:6]

### Type usage rules

- Hero words can break across lines in unexpected but balanced ways, like `sear / ch` and `dele / gati / on`. [file:5][file:6]
- Use extra-large headlines as objects, not just text.
- Keep body copy compact and highly legible.
- Avoid long-center-aligned paragraphs.
- Bold weight should be used surgically for emphasis words like “delegation.” [file:5][file:3]

### Scale suggestion

- Hero display: 96–180px desktop
- Section headline: 40–72px
- Body: 16–20px
- Eyebrow/system labels: 11–13px
- Interface buttons: 14–16px [file:5][file:6][file:3]

## Layout System

### Primary composition

The core layout is a **split-field system**:
- Left = origin, query, search, problem state
- Right = destination, routing, execution, outcome [file:5][file:6]

This split should inform the homepage hero and can recur in variations across the site.

### Grid behavior

Use a strict grid with asymmetric compositions:
- 12-column desktop grid
- strong vertical divisions
- large negative space
- occasional bleed across the midpoint [file:5][file:6]

### Spacing philosophy

Spacing should feel calm and architectural:
- generous margins
- few elements per screen
- strong alignment
- no crowded feature stacks [file:5][file:6][file:3]

## Graphic Language

### Signature motifs

The attached comps suggest several reusable brand motifs:

- Pixel search icon [file:5][file:6]
- Pixel hand/cursor icon [file:5][file:6]
- Map contour/route field [file:5][file:6]
- Locator circles and dotted connector lines [file:6][file:4]
- Gate/flight micro-labels [file:5][file:6]
- Thin corner brackets and frame marks [file:3][file:4]
- Inset tactical map window [file:5][file:6]

These should become a modular visual library for the site.

### Usage rules

- Use only 1–2 motifs per section.
- Never stack all motifs together.
- Graphics should feel functional, like interface telemetry.
- Lines should be thin, precise, and quiet.
- Decorative density should remain low. [file:5][file:6][file:4]

## Imagery Direction

### Preferred imagery

The imagery should fall into two categories:

**1. Cartographic / infrastructural textures**
- route maps
- contour maps
- transport overlays
- air traffic / waypoint references [file:5][file:6]

**2. Atmospheric destination imagery**
- landscapes
- elevated terrain
- cloud layers
- cinematic travel-like vistas [file:3][file:4]

The mountain image works because it reframes “destination” emotionally, while the map-based layouts frame it operationally. Together they create a balance of system + aspiration. [file:3][file:4][file:5]

### Avoid

- Generic team photos
- Dashboard screenshots as hero art
- 3D AI blobs
- Robot imagery
- Stock people using laptops [file:5][file:6][file:3]

## UI Components

### Buttons

Buttons should feel like framed controls, not pill SaaS CTAs:
- thin borders
- transparent or lightly tinted fills
- uppercase or compact label treatment
- minimal radius [file:5][file:6]

Examples from comps:
- `ORIGIN`
- `DESTINATION` [file:5][file:6]

### Cards

If cards are used:
- keep them flat
- minimal radius
- thin borders or tonal fills
- avoid drop-shadow-heavy depth
- use typography and spacing over decoration [file:3][file:4]

### Navigation

Navigation should be lightweight and nearly infrastructural:
- small logo top-left
- minimal links
- possible utility-style theme toggle or menu mark
- no oversized nav bar chrome [file:3][file:4]

## Motion Direction

Motion should communicate routing and transition.

### Good motion patterns
- line draw animations
- directional reveals
- content sliding from left to right
- map pan/parallax
- cursor/locator movement
- text fragments resolving into complete phrases [file:6][file:4]

### Motion tone
- precise
- smooth
- controlled
- low-bounce
- no playful springiness [file:5][file:6]

### Avoid
- floating idle animations
- glowing pulses everywhere
- excessive blur transitions
- parallax for its own sake

## Homepage Structure

### Hero

**Goal:** establish the thesis immediately.

Suggested structure:
- Split layout
- Massive “search” typography on left
- “delegation” destination state on right
- directional marker between them
- small utility buttons like ORIGIN / DESTINATION
- supporting line: “From search to delegation” [file:5][file:6]

### Section 2: Thesis

Lead with:
**Search never finished the job** [file:3][file:4]

This should be a high-impact statement section with either:
- a framed capsule headline over atmospheric image, or
- a minimal text-led section with subtle route graphics [file:3][file:4]

### Section 3: How Kaivo Works

Translate the brand metaphor into product logic:
- Intent
- Routing
- Delegation
- Execution
- Outcome

This should visually resemble a route or control flow rather than a standard feature grid. The existing brand language strongly supports a directional sequence system. [file:5][file:6]

### Section 4: Use cases

Show what gets delegated:
- research workflows
- booking/planning
- task execution
- operational coordination
- follow-through actions

Design this as routes or destination modules, not generic feature cards.

### Section 5: CTA

Use destination language:
- Set your destination
- Delegate the next step
- Move past search

Keep CTA design minimal and strong.

## Tone of Copy

Copy should be:
- sharp
- sparse
- declarative
- high-conviction
- operational, not fluffy [file:3][file:5]

Good copy style:
- “Search never finished the job.”
- “From search to delegation.”
- “Set the destination.”
- “Intent is only the starting point.” [file:3][file:5][file:6]

Avoid:
- “Transform your workflow with AI”
- “Empowering smarter productivity”
- “Unlock the future of search”

The visual system is too disciplined for generic AI copy. The language needs the same confidence and restraint. [file:5][file:6][file:3]

## Interaction Model

Every important page interaction should map to this progression:

1. User expresses intent
2. System identifies route
3. Delegation is activated
4. Outcome becomes trackable [file:5][file:6]

That means:
- forms should feel like setting an origin/destination
- progress states should feel like routing
- completed states should feel like arrival

## Brand Do’s and Don’ts

### Do
- Use oversized typography as composition [file:5][file:6]
- Use aqua as a destination/action signal [file:5][file:6]
- Build around split layouts and directional flow [file:5][file:6]
- Keep system details thin, quiet, and functional [file:3][file:4]
- Let whitespace create authority [file:5][file:6]

### Don’t
- Don’t make it look like a generic AI SaaS site
- Don’t use purple/blue gradient futurism
- Don’t over-round everything
- Don’t center every block
- Don’t rely on cards where typography can do more
- Don’t clutter pages with too many interface decorations [file:5][file:6][file:3]

## Front-End Build Notes

### Recommended stack
- Next.js or Framer site implementation
- CSS grid-based layout
- custom SVG linework and icons
- subtle GSAP or Framer Motion transitions if needed

### Styling notes
- Keep border weights thin: 1px or hairline feel
- Use high contrast between headline and background
- Prefer flat fills over glossy gradients
- Use image overlays sparingly
- Use responsive crop logic so hero type still dominates on mobile [file:5][file:6][file:3]

### Responsive behavior
On mobile:
- preserve the search → delegation narrative
- stack split layouts vertically
- keep oversized type cropped intelligently
- maintain one clear focal gesture per screen [file:1][file:4]

## One-Sentence Design Summary

Kaivo’s website should feel like a calm, high-precision routing interface that turns search into delegation through oversized editorial typography, cartographic system graphics, and a restrained aqua-on-neutral visual language. [file:5][file:6][file:3]
```


## Recommended tweaks

A few refinements are especially well supported by the comps:

- Make the homepage hero a living transition, where “search” visually hands off into “delegation” with subtle motion and route-line logic rather than just a static split-screen.[^4][^5]
- Use the “Search never finished the job” frame as a recurring thesis device across social, landing page sections, and product explainers because it is already visually cohesive in both map and atmospheric-image variants.[^2][^3]
- Standardize the small utility labels like `ORIGIN`, `DESTINATION`, `GATE`, and `FLIGHT` into a reusable microcopy system so the whole site feels like one operating environment.[^5][^4]
